# 从数字教材到 AI 教材：一个可生长的学习系统

过去我们谈“数字教材”，往往是在谈纸质教材的数字化：PDF、网页、电子书、PPT、视频。它们降低了传播成本，也让内容更容易更新，但本质上仍然是“静态知识”的屏幕化。真正值得期待的数字教材，应该不只是把书搬到网上，而是把学习过程本身变成可观察、可操作、可修改、可贡献的环境。

最近用 Quarto 和 RevealJS 做桥梁工程汇报图与三维模型嵌入，我越来越明确地感到：数字教材的下一步，不是“更漂亮的电子书”，而是“教材 + 实验台 + 学生案例库 + AI Agent”的组合。

## 本文重点

- **数字教材的核心变化**：从静态阅读材料，转向可操作、可修改、可贡献的学习环境。
- **Quarto 与 RevealJS 的角色**：Quarto 适合组织教材和出版，RevealJS 适合课堂演示和阶段性呈现。
- **三维课程的机会**：桥梁工程、工程制图、线性代数等课程可以把抽象概念转化为可旋转、可调参、可导出的交互对象。
- **AI 加入后的变化**：学生可以带入自己的数据和案例，AI 帮助生成、诊断、整理和沉淀。
- **未来教材形态**：不是一本写完的书，而是一个由教师、学生、AI 和案例共同生长的学习系统。

## Quarto 与 RevealJS：从书页到实验场

RevealJS 更像课堂展示的舞台。它适合汇报、演示、逐页推进，也适合把一个复杂项目拆成一组清晰的信息图页面。Quarto 则更像知识组织和出版的骨架。它可以把文字、公式、代码、图表、交互组件组织成网页、书籍、幻灯片、论文或技术报告。

两者结合后，教材不再只是阅读材料，而可以成为一个交互环境：一页讲解结构概念，一页嵌入 Three.js 三维模型，一页展示参数滑块，一页显示代码，一页导出 OBJ 或 FEM 节点单元。学生不是只在教材里“看见结论”，而是可以在教材里“操作对象”。

这对桥梁工程、工程制图、线性代数这类高度依赖空间理解的课程尤其重要。

桥梁工程里，学生需要理解桥向、横桥向、竖向，理解主梁、拱肋、吊杆、横梁、索塔、主缆之间的连接关系。传统教材常用二维图纸表达这些内容，但学生很难在脑中完成三维重建。如果教材里直接嵌入可旋转、可缩放、可调参数的三维桥梁模型，学生就能拖动模型、修改跨度、改变拱高、调整吊杆间距，并立即观察结构关系如何变化。

线性代数也是类似的。矩阵不只是一组数字，而是对空间的作用：旋转、伸缩、剪切、投影、折叠。交互式线性代数教材已经展示了这种可能性，例如 *Interactive Linear Algebra* 强调代数和几何的结合，让学生既能写方程，也能画图和理解线性变换；Immersive Math 则把交互图形作为线性代数学习的核心体验。这样的教材让抽象符号重新回到可感知的空间中。

## 从“看见和触摸”到“生成和修改”

Manchester 的 *Seeing and Touching Structural Concepts* 给了一个非常好的参照。它通过简单物理模型和工程实例，帮助学生形成对结构概念的直觉理解。它关心的不是先把复杂计算讲完，而是让学生先看见、触摸、感受结构概念。

这种思路非常重要。现代工程教育里，学生越来越会用软件，但不一定能判断软件结果是否合理。会点按钮，并不等于理解模型假设；会运行有限元，也不等于知道节点、单元、约束和传力路径是否正确。结构概念教学的核心，恰恰是让学生形成判断力。

AI 加入之后，这种教材可以从“看见和触摸”继续推进到“生成和修改”。

学生不只是观看老师准备好的物理模型或网页模型，而是可以输入自己的桥梁参数，生成自己的三维模型，导出自己的 OBJ 文件，得到自己的 FEM 节点和单元，再把错误、修改和反思沉淀成新的教材案例。

这时教材不再是一次性写完的内容，而是一个可以持续吸收学生实践的学习系统。

## 学生案例合集：教材开始生长

未来的 AI 数字教材，很可能会变成一种“案例生长型教材”。

教师提供基础概念、工作流、案例模板和质量标准；学生每年提交自己的案例；AI 帮助整理、转写、生成草稿和检查格式；教师与助教负责审核概念准确性和工程合理性。最后，优秀案例进入教材，成为下一届学生的学习资源。

一个桥梁工程案例单元可以这样组织：

```text
案例名称
工程背景
结构概念
输入数据
提示词版本 1
第一次失败结果
错误分析
提示词版本 2
三维模型
参数化控制
OBJ 展示
FEM 节点/单元
结论与反思
```

这样，学生提交的不再只是一份作业，而是一个可阅读、可运行、可复用的小教材单元。

传统作业交完就结束了。案例生长型教材则把学生作业转化为公共学习资产。第一届学生可能只贡献 10 个案例，第二届变成 50 个，几年后就形成一个面向真实工程问题的案例库。

对于桥梁工程，这个案例库可以包括提篮拱桥、斜拉桥、悬索桥、梁桥、组合桥、异形桥、CAD 复刻、FEM 导出、OBJ 展示和 3D 打印。对于线性代数，它可以包括矩阵变换案例、投影案例、特征向量案例、图形变形案例、最小二乘案例、奇异值分解案例。每个案例都既有概念解释，又有可交互对象。

## AI 不是聊天框，而是任务型 Agent

AI 加入教材后，最容易犯的错误，是在每一页旁边放一个“问我任何问题”的聊天框。这样的聊天框当然有用，但它会让学习变散，也容易把学生带离本章任务。

更好的方式，是把 AI 做成任务型 Agent。

例如在“提篮拱桥建模”这一章，Agent 不需要回答所有土木工程问题，它只需要带学生完成这一章的任务：

```text
学生输入桥梁参数
↓
AI 检查缺失信息
↓
生成桥梁规格 JSON
↓
模板生成 HTML 三维模型
↓
导出 OBJ / FEM 数据
↓
学生旋转检查模型
↓
AI 根据错误反馈帮助修改
↓
沉淀成可复用提示词或 skill
```

这里的 DeepSeek、OpenAI 或其他模型只是生成与解释引擎。真正的教材系统还包括代理服务、模板、工具、文件系统、限流机制、审核流程和发布机制。换句话说，不是“模型内部复刻了 skill”，而是我们用 Agent 外壳把一次性生成变成了可重复、可检查、可扩展的任务流程。

对于课堂，这一点也关系到安全。学生不应该直接拿到教师的 API Key，也不应该把 key 写进网页前端。更合理的方式是教师提供一个限额代理：学生访问课程页面，页面请求教师代理，代理再调用模型。代理负责模型白名单、每日额度、单次 token 限制、学生身份、日志记录和一键停用。课后自由探索时，学生可以使用自己的 key 和本地代理。

## 《爆裂》九原则与 AI 教材

如果借用《爆裂》的九个原则，未来 AI 数字教材的形态会更清楚。

**涌现优于权威。**  
教材不再只是专家一次性写定，而是由教师、学生、AI、真实案例共同生长。权威仍然重要，但权威的角色从“写完全部内容”转向“设计系统、审核质量、保持方向”。

**拉力优于推力。**  
学生不是被动接收章节，而是在自己的项目需要中主动调用知识、模型和工具。桥梁参数、CAD 图纸、矩阵变换、实验数据，都会成为学生拉动教材内容的入口。

**指南针优于地图。**  
教材不必规定唯一学习路径，而是提供方向、原则、案例库和工作流。学生可以从拱桥进入，也可以从斜拉桥进入；可以先做模型，也可以先做错误分析。教材提供指南针，而不是唯一地图。

**风险优于安全。**  
错误不再只是要避免的东西，而是学习材料。吊杆悬空、坐标错乱、拉索交叉、节点重复、矩阵变换方向误判，都可以进入错误案例库。AI 教材应该允许学生在低风险环境里犯真实错误。

**违抗优于服从。**  
学生不只是照着例题做，而是可以挑战教材、修改模型、提出新桥型、新矩阵、新解释。一个好的 AI 教材，应该允许学生对标准答案说“不对，我来试另一种”。

**实践优于理论。**  
先做一座桥，先调一个参数，先导出一个 OBJ，先观察一个矩阵如何改变空间，然后再回到理论解释。理论不是消失，而是从实践问题中被重新需要。

**多样性优于能力。**  
不同学生带来不同案例、图纸、参数、背景和错误。一个班级里，最有价值的未必只是能力最强的学生，而是案例最多样的学生群体。多样性本身会扩展教材的边界。

**韧性优于力量。**  
教材不是追求一次性完美，而是能持续修订、分叉、合并、扩展、纠错。Quarto、GitHub、自动发布和 AI 辅助编辑，使教材具备持续演化的能力。

**系统优于个体。**  
真正重要的不是某个老师写得多好，而是形成一套系统：学生贡献案例，AI 整理材料，助教检查可运行性，教师审核概念，平台自动发布，后续学习者继续修改和扩展。

## 一种可能的实现架构

这样的教材可以用比较清晰的技术结构实现：

```text
Quarto：教材叙事、章节组织、书籍发布
RevealJS：课堂汇报、阶段性展示、演示型页面
Three.js / Plotly：三维模型与数据可视化
Node / 云函数代理：安全调用 AI API
JSON / CSV / OBJ：学生数据与模型产物
GitHub：版本管理、协作、Pull Request
GitHub Actions：自动渲染与发布
AI Agent：生成、诊断、整理和检查
教师/助教审核：概念准确性与工程合理性
```

学生的贡献路径可以分为三类：

```text
轻量贡献：填写表单，上传截图、参数、反思
标准贡献：提交 Quarto 案例页面和模型文件
高级贡献：提交新的交互组件、Agent 流程或 skill
```

后台则可以运行一个半自动流程：

```text
学生提交案例
↓
AI 整理成 Quarto 草稿
↓
自动检查链接、图片、代码、模型文件
↓
助教检查页面能否渲染和模型能否打开
↓
教师检查概念准确性
↓
合并到教材仓库
↓
GitHub Pages 自动发布
```

这不是简单地把“教材写成网页”，而是把教材变成一个知识生产系统。

## 对桥梁工程和线性代数的影响

桥梁工程的教材可以从“讲桥”变成“造桥”。学生先生成一座提篮拱桥，再修改不同尺寸，再抽象出泛化提示词，再迁移到斜拉桥和悬索桥，最后导出 FEM 节点单元和 OBJ 模型。整个过程把空间认知、结构概念、参数化设计、工程导出和 AI 工作流连在了一起。

线性代数的教材可以从“算矩阵”变成“操作空间”。学生输入矩阵，观察平面网格如何变形；调整特征值，观察特征方向如何保持；上传点云或图形，观察线性变换前后的变化；再让 AI 解释这个变换的代数意义和几何意义。这样，矩阵、向量、基、投影、特征值不再只是符号，而成为学生可以操纵的对象。

这两类课程共同说明：AI 教材最重要的不是“它会回答问题”，而是“它能让学生把自己的材料放进去，生成一个可检查的学习对象”。

## 结语：从教材到学习生态

传统教材交付知识，交互教材交付体验，而 AI 教材应该交付可迁移的工作能力。

未来的教材不会只是老师写完、学生阅读、考试检验。它更像一个持续生长的学习生态：老师设计方向和标准，学生贡献案例和错误，AI 帮助整理和生成，平台负责协作与发布。它既保留教材的稳定叙事，又允许真实案例不断涌入；既能展示标准概念，又能容纳学生自己的数据和问题。

对于桥梁工程、线性代数以及所有依赖空间理解和实践操作的课程，这种变化尤其关键。学生不只是学会一个知识点，而是学会如何把一个模糊问题变成结构化数据，如何借助 AI 生成模型，如何检查错误，如何导出工程产物，如何把经验沉淀成下一位学习者可以复用的案例。

这也许就是 AI 时代数字教材最重要的变化：它不再只是一本书，而是一个让知识、工具、案例和学习者共同生长的系统。
